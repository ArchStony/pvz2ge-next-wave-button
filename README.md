# 下一波按钮 1.2.0

## 最低使用版本
- `PvZ2 Gardendless 0.15.0`
- `GP-Next 1.5.5`

## 主要功能
- 参考PVZ2中文版的下一波按钮，在部分关卡中加入了该功能，减少等待时间。
- 下一波按钮在暂停按钮下方，点击即可推进下一波，不受窗口比例影响。
- 默认使用 `Tab` 键触发， F9 面板中可绑定其他按键。
- 图标下方显示该关卡剩余次数，每波生成完毕后减一。
- 提供两个版本：标准模式（符合中文版逻辑）、扫荡模式（长按可累计波数）。默认为标准模式。
- F9 可开启“保持按钮常态显示”：标准模式也持续显示蓝色按钮，方便查看剩余波次；默认关闭。
- F9 可设置是否压缩突袭小队的分组间隔，支持关闭、仅扫荡模式开启和全局；默认仅扫荡模式开启。

### 标准模式
- 标准模式使用蓝色“下一波”旗帜图标。
- 标准模式默认需等当前波所有有效僵尸`进入地图`且`可被攻击`后，方显示按钮；开启“保持按钮常态显示”后蓝色按钮持续可见，但在可推进前保持禁用。
- 标准模式下，倒数第二波全部进入地图且可被攻击后，“最终波”按钮会出现；点击可手动加载最终波，不点击时仍由原生倒计时和血量判定自动加载。

### 扫荡模式
- 扫荡模式使用红色“扫一波”旗帜图标。
- 扫荡模式按钮一直显示，按住按钮或快捷键 150 ms 后开始连续增加接续波数。
- 扫荡模式使用了更激进的僵尸生成方式（见下文），可直接进入最终波。


## 适用关卡
- 适用于普通波次关卡、普通危险房和无尽模式。
- 各种小游戏、BOSS关卡、禅境花园、沙盒等特殊模式不会显示按钮，也不会占用快捷键。
- 彩陶盛宴测试通过，本地导入的社区关卡未测试————理论上符合官方声明的关卡均可使用。有问题请在评论区反馈。


## 安装
1. 在 GP-Next 中开启 `实验性 → JS Modding`。
2. 打开 F9 面板，从“模组”页导入 `next-wave-button-1.2.0.zip`。
3. 勾选“下一波按钮”模组并应用。


## 对原版行为的修改
- 只会对符合条件的关卡（见上文“适用关卡”）启用。
- 两项修改都通过运行时包装完成，不修改游戏文件。

### 僵尸排队位置：`zombieSpawnOffset`
- `Zombies.spawnZombieFromLaneByID()` 生成僵尸时，会同时设置同一行下一只僵尸的出生偏移。原版使用 `zombieSpawnOffset += 2 * SquareWidth`，即每只间隔 2 格。
- 模组在该函数返回后，把新增偏移从 2 格改为设置值。默认值为 `0.5` 格，F9 中可在 `0～2` 格范围内调整并持久化；标准和扫荡模式共用该参数。
- 修改只影响后续同行僵尸的排队位置，不会移动当前已经生成的僵尸。

### 波次等待函数：`sleep()`
- `level.sleep()` 负责波次流程中僵尸生成期间的异步等待：用于控制出怪步骤、raid 分组和最终阶段之间的时间间隔。
- “压缩突袭小队的分组间隔”默认仅在扫荡模式开启。选择“全局”后，标准和扫荡模式都会压缩；选择“关闭”后，即使扫荡模式加速其他波次等待，突袭小队仍使用原版分组间隔。
- “全局”仍只作用于本模组已启用、会显示“下一波”按钮的关卡；其他小游戏和特殊模式不会应用该压缩。
- 开启压缩时，每组突袭小队之间的原版等待会缩短为一帧渲染；关闭时保留原版等待。
- 扫荡模式在波次队列处理、raid/WaveAction 排空或最终波前，将 `sleep()` 一帧渲染，以缩短排队时间。

### 突袭小队分批生成：`readWave_RaidingPartyZombieSpawnerProps()`
- 原版通过 `GroupSize`、`SwashbucklerCount` 和 `TimeBetweenGroups` 计算每个突袭分组的生成时间，并在组间调用 `await this.sleep(间隔)`，因此同一波内的突袭小队会按配置逐组进入地图。
- 模组包装该方法，不修改关卡文件或突袭僵尸数量。开启压缩时，仅在该方法执行期间临时替换当前关卡的 `sleep()`，把组间等待缩短为一帧；突袭僵尸仍按原版生成、入场和注册流程执行。
- 设置选择“关闭”时，突袭分组完全保留原版间隔；选择“仅扫荡模式开启”时只影响扫荡模式；选择“全局”时标准和扫荡模式都压缩。
- 压缩只适用于本模组已启用、会显示“下一波”按钮的关卡。方法结束、异常或模组停用时会恢复关卡原本的 `sleep()`，不会影响其他波次等待。
